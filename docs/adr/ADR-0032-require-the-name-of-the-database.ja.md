# ADR-0032: データベースの名前を必須とし、ユーザーの名前で代用しない

## 背景と課題

ADR-0021 は、接続を libpq の環境変数から読むと決めた。チームが `psql` のために用意しているものが、そのまま kortopi でも使えるようにするためである。
libpq と、kortopi が使うドライバー（ADR-0025）は、どの設定もデータベースを指定しなければ、ユーザーの名前をデータベースの名前として使う。

kortopi を試したあるチームは、`--host`・`--port`・`--user`・`--schema` を付け、`--dbname` も `PGDATABASE` もなしに `kortopi plan` を実行した。
接続先はユーザーの名前のデータベースになったが、それは存在せず、エラーはユーザーが一度も挙げていないそのデータベースについてのものだった。

kortopi は、libpq のこの代用に従うのか。

## 判断の基準

- 行を書く道具は、誰も指定していないデータベースを選ばない。
- エラーは、利用者が書いたものか、書かなかったものを挙げる。
- libpq の環境変数は、その意味を保つ（ADR-0021）。

## 検討した選択肢

- データベースの名前を必須とする
- libpq と同じく、ユーザーの名前で代用する

## 決定

採用：「データベースの名前を必須とする」。kortopi が書き込むデータベースは、誰かが指定したものでなければならない。しかも、名前がないことを告げるエラーは何を渡せばよいかを示すが、代用は利用者が一度も挙げていないデータベースについてのエラーを出すからである。

決まりは次のとおりである。

- kortopi は、データベースの名前を `--dbname`・`PGDATABASE`・`PGSERVICE` が指すサービスの `dbname` のどれかから得る。
- どれもデータベースを指定しなければ、kortopi は接続する前に止まる。エラーは、データベースの名前がないことと、その渡し方を告げる。
- kortopi は、ユーザーの名前で代用しない。接続のほかの設定は、libpq の既定を保つ。
- これは ADR-0021 を細かくする。ADR-0021 は、例外なく libpq の環境変数から接続を読むとしている。

### 結果

- 良い点：誰も指定していないデータベースに対して、計画・apply・書き出しが動くことはない。
- 良い点：名前がないときのエラーは、どの接続よりも前に、何を渡せばよいかを示す。
- 悪い点：ユーザーの名前のデータベースを使い、代用に頼っている構成は、データベースを指定しなければならない。`PGDATABASE`・`--dbname`・サービスのどれかで指定する。
- 悪い点：この点で kortopi は `psql` と違い、利用者向けの説明でそう述べる必要がある。

### 確認の方法

- `internal/postgres` の単体テスト（`TestConnectionSettingErrors`）が、名前がないときのエラーを確かめる。`--dbname` とサービスが名前を渡すことは `TestLibpqVariables` が確かめる。
- `cmd/kortopi` では、`TestPlanCommandConnectionErrors` が、名前のない計画が接続する前に止まることを PostgreSQL に対して確かめる。`TestNoSecretInOutput` は、そのエラーが環境の何も繰り返さないことを確かめる。

## 選択肢の長所と短所

### データベースの名前を必須とする

- 良い点：どの実行のデータベースも、利用者が指定したものになる。
- 悪い点：代用に頼っていた構成は、変える必要がある。

### libpq と同じく、ユーザーの名前で代用する

- 良い点：kortopi が `psql` と同じに振る舞う。
- 悪い点：名前を忘れた実行が、ユーザーの名前のデータベースに届くか、利用者が一度も挙げていないデータベースについてのエラーで失敗する。
