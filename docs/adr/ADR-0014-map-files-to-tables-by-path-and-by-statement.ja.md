# ADR-0014: CSV ファイルはパスで、SQL ファイルは文で、テーブルに対応づける

## 背景と課題

宣言は、データのディレクトリの下にある SQL ファイルと CSV ファイルのツリーである（ADR-0008）。kortopi は、各ファイルがどのテーブルを宣言するかを知る必要がある。
マスタテーブルは複数のスキーマにまたがることがあるので、テーブルはスキーマとテーブルの名前の組で呼ぶ。

2つの書式は、持つ情報が違う。
CSV ファイルは見出しの行と行を持つだけで、中にテーブルの名前はない。
SQL ファイルは INSERT 文ごとにテーブルの名前を持つ。また、`pg_dump` の出力は、多くのテーブルの行を1つのファイルにまとめる。

kortopi は、ファイルがどのテーブルを宣言するかをどう決めるか。

## 判断の基準

- CSV ファイルのテーブルが、ファイルの置き場所からわかる。
- `pg_dump` の出力を、テーブルごとに分けないまま受け付ける。
- 各テーブルの宣言は1つだけであり、どのファイルが優先されるかの決まりが要らない。
- ファイルとテーブルの対応づけに、設定が要らない。

## 検討した選択肢

- CSV ファイルはパスで、SQL ファイルは文ごとのテーブル名で
- どちらの書式も1テーブル1ファイルとし、パスで対応づける
- `kortopi.toml` の一覧で、ファイルごとにテーブルを対応づける

## 決定

採用：「CSV ファイルはパスで、SQL ファイルは文ごとのテーブル名で」。どちらの書式も、テーブルの名前をそれぞれ自然な場所にすでに持っているからである。CSV ファイルではパス、SQL では文である。

決まりは次のとおりである。

- CSV ファイルは、データのディレクトリからのパスが示すテーブルを宣言する。パスは `<schema>/<table>.csv` である。たとえば、`facility/room_types.csv` はテーブル `facility.room_types` を宣言する。
- SQL ファイルでは、各 INSERT 文が、その文の挙げるテーブルの行を宣言する。1つの SQL ファイルで複数のテーブルを宣言してよい。そのため、`pg_dump` の出力をそのまま受け付けられる。
- 2つのファイルで宣言したテーブルは、2つのファイルの書式にかかわらずエラーである。
- 環境ごとに宣言を重ねる仕組みは、最初の版に入れない。共通のファイルと、ある環境のためのファイルの両方が同じテーブルを宣言する、といった使い方である。

次の2つの細部は、SQL を読む処理の実装のときに決める（ADR-0015）。SQL ファイルをデータのディレクトリの下のどこに置けるかと、スキーマのないテーブル名を持つ INSERT 文をどう扱うかである。

### 結果

- 良い点：データのディレクトリの下にある CSV ファイルのツリーが、それらが宣言するスキーマとテーブルを示す。
- 良い点：多くのテーブルのダンプを、1つのファイルのままデータのディレクトリに置ける。
- 良い点：各テーブルの宣言は1つなので、どのファイルが優先されるかが問題にならない。
- 悪い点：2つの書式は違う決まりに従うので、読む人は両方を知っている必要がある。
- 悪い点：SQL ファイルがどのテーブルを宣言するかは、ツリーからはわからない。読む人はファイルを開く必要がある。
- 悪い点：重ねる仕組みが最初の版にないので、同じテーブルに違う行が要る環境は、まだ宣言できない。

### 確認の方法

宣言の読み込みのテストで、CSV のパスとテーブルの対応、複数のテーブルを宣言する SQL ファイル、2つのファイルで宣言したテーブルのエラーを確かめる。
これらのテストは、plan の実装とともに加わる。

## 選択肢の長所と短所

### CSV ファイルはパスで、SQL ファイルは文ごとのテーブル名で

- 良い点：設定が要らず、`pg_dump` の出力がそのまま使える。
- 悪い点：書式ごとに1つずつ、2つの決まりがある。

### どちらの書式も1テーブル1ファイルとし、パスで対応づける

- 良い点：1つの決まりで両方の書式をまかなえ、ツリーがすべてのテーブルを示す。
- 悪い点：`pg_dump` の出力は、使う前にテーブル単位で分ける必要がある。
- 悪い点：SQL ファイルのパスと、その文の中のテーブルが食い違いうる。kortopi は、その場合の決まりを必要とする。

### `kortopi.toml` の一覧で、ファイルごとにテーブルを対応づける

- 良い点：ファイルをどう並べても動く。
- 悪い点：すべてのファイルに項目が要る。ファイルを足し、動かし、消すたびに、一覧も追いつかせる必要がある。
- 悪い点：設定ファイルが省略可能ではなくなる（ADR-0013）。

## 補足

- 設定ファイル `kortopi.toml` は、同じデータのディレクトリの最上位に置く（ADR-0013）。
- kortopi が SQL ファイルの INSERT 文をどう読み、どの文を受け付けるかは ADR-0015 にある。
